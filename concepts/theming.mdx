Fyne's theme system is the single source of truth for every visual property in your application — colors, fonts, icons, and sizes. Rather than hard-coding `color.RGBA` values throughout your widgets, you look up named tokens from the active theme. When the user or OS switches between light and dark mode, every widget that reads from the theme updates automatically, without any extra code on your part.

## Built-in Themes

Fyne ships one adaptive theme — `theme.DefaultTheme()` — that respects the user's OS-level dark/light preference. Two legacy constructors lock the variant explicitly:

```go
import (
    "fyne.io/fyne/v2/theme"
)

// Adapts to the OS preference (recommended)
a.Settings().SetTheme(theme.DefaultTheme())

// Force dark variant (ignores user preference — deprecated, will be removed in v3)
a.Settings().SetTheme(theme.DarkTheme())

// Force light variant (same caveat)
a.Settings().SetTheme(theme.LightTheme())
```

<Warning>
  `theme.DarkTheme()` and `theme.LightTheme()` are deprecated since Fyne 2.0.
  They ignore the user's OS preference and will be removed in v3. Build a
  custom theme (see below) if you need to override the variant.
</Warning>

### Theme Variants

The `fyne.ThemeVariant` type distinguishes between light and dark appearances. Two named constants are exported from the `theme` package:

```go
theme.VariantDark  // fyne.ThemeVariant = 0
theme.VariantLight // fyne.ThemeVariant = 1
```

Read the current variant to make runtime decisions:

```go
variant := a.Settings().ThemeVariant()
if variant == theme.VariantDark {
    fmt.Println("Dark mode is active")
}
```

## The Theme Interface

A Fyne theme is any value that satisfies four methods:

```go
type Theme interface {
    Color(ThemeColorName, ThemeVariant) color.Color
    Font(TextStyle) Resource
    Icon(ThemeIconName) Resource
    Size(ThemeSizeName) float32
}
```

Every widget in Fyne calls these methods at render time. Implementing all four is all you need to completely control the look and feel.

Use `theme.Color(name)` (since 2.5) to read the current color without a manual theme lookup:

```go
bg    := theme.Color(theme.ColorNameBackground)
fg    := theme.Color(theme.ColorNameForeground)
pri   := theme.Color(theme.ColorNamePrimary)
focus := theme.Color(theme.ColorNameFocus)
err   := theme.Color(theme.ColorNameError)
```

<Note>
  The older per-color helpers such as `theme.BackgroundColor()`,
  `theme.ForegroundColor()`, and `theme.PrimaryColor()` still work but are
  deprecated since Fyne 2.0 and will be removed in v3. Prefer
  `theme.Color(theme.ColorNameXxx)` in new code.
</Note>

### Primary Color Palette

Fyne provides named primary colors that users can pick in settings. The available names are returned by `theme.PrimaryColorNames()` and include `"blue"` (default), `"red"`, `"orange"`, `"yellow"`, `"green"`, `"purple"`, `"brown"`, and `"gray"`.

```go
// Read the current primary color name
primaryName := a.Settings().PrimaryColor()

// Look up its RGBA value
col := theme.PrimaryColorNamed(primaryName)
```

## Size Tokens

`ThemeSizeName` constants control spacing, typography scale, and UI chrome dimensions:

| Constant | Description |
|----------|-------------|
| `theme.SizeNameText` | Default body text size |
| `theme.SizeNameHeadingText` | Heading text size |
| `theme.SizeNameSubHeadingText` | Sub-heading text size |
| `theme.SizeNameCaptionText` | Caption / helper text size |
| `theme.SizeNamePadding` | Standard outer padding |
| `theme.SizeNameInnerPadding` | Compact inner padding |
| `theme.SizeNameInlineIcon` | Icon size inline with text |
| `theme.SizeNameScrollBar` | Scrollbar thumb width |
| `theme.SizeNameScrollBarSmall` | Compact scrollbar width |
| `theme.SizeNameSeparatorThickness` | Divider line thickness |
| `theme.SizeNameInputBorder` | Text field border width |
| `theme.SizeNameLineSpacing` | Extra line gap in multi-line text |

Convenience helpers:

```go
textSize   := theme.TextSize()
padding    := theme.Padding()
iconSize   := theme.IconInlineSize()
```

## Creating a Custom Theme

Implement the `fyne.Theme` interface to fully control your app's appearance. The recommended approach is to embed `theme.DefaultTheme()` and override only the values you care about.

### Minimal Custom Theme (Override Primary Color)

```go
package main

import (
    "image/color"

    "fyne.io/fyne/v2"
    "fyne.io/fyne/v2/app"
    "fyne.io/fyne/v2/theme"
)

// myTheme overrides just the primary color; everything else delegates
// to the built-in default theme.
type myTheme struct{}

var _ fyne.Theme = (*myTheme)(nil)

func (myTheme) Color(name fyne.ThemeColorName, variant fyne.ThemeVariant) color.Color {
    if name == theme.ColorNamePrimary {
        return color.NRGBA{R: 0xFF, G: 0x6B, B: 0x6B, A: 0xFF} // coral red
    }
    return theme.DefaultTheme().Color(name, variant)
}

func (myTheme) Font(style fyne.TextStyle) fyne.Resource {
    return theme.DefaultTheme().Font(style)
}

func (myTheme) Icon(name fyne.ThemeIconName) fyne.Resource {
    return theme.DefaultTheme().Icon(name)
}

func (myTheme) Size(name fyne.ThemeSizeName) float32 {
    return theme.DefaultTheme().Size(name)
}

func main() {
    a := app.New()
    a.Settings().SetTheme(&myTheme{})

    w := a.NewWindow("Custom Theme")
    // …
    w.ShowAndRun()
}
```

### Full Custom Theme Example

```go
type brandTheme struct {
    variant fyne.ThemeVariant
}

func (t *brandTheme) Color(name fyne.ThemeColorName, variant fyne.ThemeVariant) color.Color {
    // Respect caller-requested variant; fall back to our stored preference
    if t.variant != theme.VariantLight && t.variant != theme.VariantDark {
        variant = fyne.CurrentApp().Settings().ThemeVariant()
    } else {
        variant = t.variant
    }

    switch name {
    case theme.ColorNameBackground:
        if variant == theme.VariantDark {
            return color.NRGBA{R: 0x1E, G: 0x1E, B: 0x2E, A: 0xFF}
        }
        return color.NRGBA{R: 0xF8, G: 0xF8, B: 0xFF, A: 0xFF}
    case theme.ColorNamePrimary:
        return color.NRGBA{R: 0x89, G: 0xB4, B: 0xFA, A: 0xFF}
    case theme.ColorNameForeground:
        if variant == theme.VariantDark {
            return color.NRGBA{R: 0xCD, G: 0xD6, B: 0xF4, A: 0xFF}
        }
        return color.NRGBA{R: 0x1E, G: 0x1E, B: 0x2E, A: 0xFF}
    }
    // Fall back to the default for everything else
    return theme.DefaultTheme().Color(name, variant)
}

func (t *brandTheme) Font(style fyne.TextStyle) fyne.Resource {
    // Swap in a custom font; fall back to default for styles we don't have
    if !style.Bold && !style.Italic && !style.Monospace {
        return resourceInterRegularTtf // bundled with fyne bundle
    }
    return theme.DefaultTheme().Font(style)
}

func (t *brandTheme) Icon(name fyne.ThemeIconName) fyne.Resource {
    return theme.DefaultTheme().Icon(name)
}

func (t *brandTheme) Size(name fyne.ThemeSizeName) float32 {
    if name == theme.SizeNamePadding {
        return 8 // slightly more generous padding
    }
    return theme.DefaultTheme().Size(name)
}
```

## Migrating from v1 Themes with `theme.FromLegacy`

If you have a theme built against the original `fyne.LegacyTheme` interface (used before Fyne 2.0), wrap it with `theme.FromLegacy` to make it compatible with the current `fyne.Theme` interface:

```go
// oldTheme implements fyne.LegacyTheme
type oldTheme struct{}
func (oldTheme) BackgroundColor() color.Color { return color.White }
// … other LegacyTheme methods …

// Wrap for use with 2.x+ API
modernTheme := theme.FromLegacy(&oldTheme{})
a.Settings().SetTheme(modernTheme)
```

`theme.FromLegacy` maps each legacy color method to its corresponding `ThemeColorName` and delegates size/font/icon lookups to `theme.DefaultTheme()` for names the legacy interface never knew about.

<Warning>
  `theme.FromLegacy` is itself a transition aid and may be removed in Fyne v3.
  Use it only as an intermediate step while migrating a v1 theme to the current
  `fyne.Theme` interface.
</Warning>

## Per-Widget Theme Override

Since Fyne 2.5, individual widgets or sub-trees can use a different theme from the rest of the application via `container.NewThemeOverride`. Wrap any `CanvasObject` with a `ThemeOverride` container and every descendant widget will render using the supplied theme.

```go
import "fyne.io/fyne/v2/container"

// Apply a compact theme to just this card widget (and its children)
overridden := container.NewThemeOverride(myCard, &compactTheme{})
```

The per-widget theme is inherited by the wrapped object's children, making it possible to theme entire sub-trees differently without changing the global application theme. If content is added to a nested container after the `ThemeOverride` is created, call `overridden.Refresh()` to propagate the theme to the new items.

## Listening for Theme Changes

React to runtime theme changes (e.g., the user switching OS dark mode) by registering a settings listener:

```go
a.Settings().AddListener(func(s fyne.Settings) {
    fmt.Println("Theme variant is now:", s.ThemeVariant())
    // Refresh any cached colors or icons here
})
```
