Fyne's theme system is the single source of truth for every visual property in an application — from button colours and text sizes to icons and font faces. Rather than styling individual widgets, you implement the `fyne.Theme` interface once and apply it globally, giving your app a consistent look that automatically adapts to light and dark variants and any future widget additions.

## The `fyne.Theme` interface

The interface is defined in `fyne.io/fyne/v2` and has four methods:

```go
// Theme defines the method to look up colors, sizes and fonts that make up a Fyne theme.
type Theme interface {
    Color(ThemeColorName, ThemeVariant) color.Color
    Font(TextStyle) fyne.Resource
    Icon(ThemeIconName) fyne.Resource
    Size(ThemeSizeName) float32
}
```

Every widget queries the active theme through these four methods. You only need to override the values you want to change; delegate everything else to `theme.DefaultTheme()`.

## Theme variants

Fyne passes a `fyne.ThemeVariant` to `Color` so you can return different colours for light and dark mode. Use the constants from `fyne.io/fyne/v2/theme`:

| Constant | Meaning |
|---|---|
| `theme.VariantDark` | User prefers a dark colour scheme |
| `theme.VariantLight` | User prefers a light colour scheme |

## Full working example: a green-accented theme

```go
package main

import (
    "image/color"

    "fyne.io/fyne/v2"
    "fyne.io/fyne/v2/app"
    "fyne.io/fyne/v2/theme"
    "fyne.io/fyne/v2/widget"
)

// myTheme overrides the primary colour and defers everything else to the default theme.
type myTheme struct{}

// Compile-time check that myTheme satisfies fyne.Theme.
var _ fyne.Theme = (*myTheme)(nil)

func (m myTheme) Color(name fyne.ThemeColorName, variant fyne.ThemeVariant) color.Color {
    if name == theme.ColorNamePrimary {
        return color.NRGBA{R: 0x22, G: 0xc5, B: 0x5e, A: 0xff} // green
    }
    return theme.DefaultTheme().Color(name, variant)
}

func (m myTheme) Font(style fyne.TextStyle) fyne.Resource {
    return theme.DefaultTheme().Font(style)
}

func (m myTheme) Icon(name fyne.ThemeIconName) fyne.Resource {
    return theme.DefaultTheme().Icon(name)
}

func (m myTheme) Size(name fyne.ThemeSizeName) float32 {
    return theme.DefaultTheme().Size(name)
}

func main() {
    a := app.New()
    a.Settings().SetTheme(&myTheme{}) // apply globally

    w := a.NewWindow("Green Theme Demo")
    w.SetContent(widget.NewButton("Click me", nil))
    w.ShowAndRun()
}
```

<Note>
  The compile-time assertion `var _ fyne.Theme = (*myTheme)(nil)` causes a build error if your struct is missing any required method. Add it to every custom theme struct.
</Note>

## Applying the theme

Call `SetTheme` on your application's settings object. This must be done before any window is shown to avoid a visible flash of the default theme:

```go
a := app.New()
a.Settings().SetTheme(&myTheme{})
```

## Using custom fonts

Load a TTF file as a `fyne.Resource` (using `fyne.LoadResourceFromPath` or `fyne bundle`) and return it from `Font` based on the requested `fyne.TextStyle`:

```go
import (
    "fyne.io/fyne/v2"
    "fyne.io/fyne/v2/theme"
)

var myRegularFont fyne.Resource // loaded at startup

func (m myTheme) Font(style fyne.TextStyle) fyne.Resource {
    if !style.Bold && !style.Italic && !style.Monospace {
        return myRegularFont
    }
    return theme.DefaultTheme().Font(style)
}
```

Load your font resource during `init` or in `main` before calling `SetTheme`:

```go
func init() {
    r, err := fyne.LoadResourceFromPath("assets/Inter-Regular.ttf")
    if err != nil {
        panic(err)
    }
    myRegularFont = r
}
```

## Using custom icons

Bundle SVG or PNG assets with the `fyne bundle` tool, then return the bundled resource from `Icon`:

```bash
fyne bundle -o bundled.go assets/myicon.svg
```

```go
func (m myTheme) Icon(name fyne.ThemeIconName) fyne.Resource {
    if name == theme.IconNameHome {
        return resourceMyiconSvg // generated by fyne bundle
    }
    return theme.DefaultTheme().Icon(name)
}
```

## `ThemeSizeName` reference

Size constants control spacing, text sizes, and component dimensions:

| Constant | Default | Purpose |
|---|---|---|
| `theme.SizeNamePadding` | 4 px | Standard gap between elements |
| `theme.SizeNameInnerPadding` | 8 px | Inside widget padding |
| `theme.SizeNameInlineIcon` | 20 px | Icons within buttons/labels |
| `theme.SizeNameText` | 14 px | Body text |
| `theme.SizeNameHeadingText` | 24 px | Heading text |
| `theme.SizeNameSubHeadingText` | 18 px | Sub-heading text |
| `theme.SizeNameCaptionText` | 11 px | Caption / helper text |
| `theme.SizeNameScrollBar` | 12 px | Scrollbar width/height |
| `theme.SizeNameScrollBarSmall` | 3 px | Minimised scrollbar |
| `theme.SizeNameSeparatorThickness` | 1 px | Separator widget thickness |
| `theme.SizeNameInputBorder` | 1 px | Entry field border |

```go
func (m myTheme) Size(name fyne.ThemeSizeName) float32 {
    if name == theme.SizeNamePadding {
        return 8 // double the standard padding
    }
    return theme.DefaultTheme().Size(name)
}
```

<Tip>
  When overriding sizes, change one value at a time and test across window sizes. Increasing padding without also increasing icon or text sizes can produce layouts that feel unbalanced.
</Tip>

<Warning>
  `theme.DefaultTheme()` returns a live reference that adapts to the system's light/dark preference. If you store it as a field at startup and the user switches variants at runtime, your fallback colours may be stale. Always call `theme.DefaultTheme()` inline rather than caching it.
</Warning>
