Fyne is a cross-platform UI toolkit and application API written entirely in Go. It lets you write a single codebase and ship native-feeling applications to desktops, phones, and the browser — without managing platform-specific build systems or bundling external runtimes.

## What is Fyne?

Fyne provides a complete application framework on top of Go's standard toolchain. You define your UI with composable widgets and layout containers, attach business logic through plain Go functions, and let Fyne's driver layer translate everything into pixels on whatever device your users run. Because every Fyne app carries its own renderer, there are no system libraries for end-users to install — just download and run.

The project is open source under the BSD-3-Clause licence and is actively maintained by the community at [fyne.io](https://fyne.io).

## Supported Platforms

Fyne applications run on all major platforms from a single Go source tree:

| Platform | Notes |
|---|---|
| **Windows** | 10 and later; requires a C compiler (TDM-GCC or MSYS2) |
| **macOS** | 11 (Big Sur) and later; Xcode Command Line Tools required |
| **Linux** | X11 and Wayland; requires gcc and Mesa/X11 headers |
| **Android** | ARMv7 and ARM64; packaged with the `fyne` CLI |
| **iOS** | Build from macOS with Xcode installed |
| **WebAssembly** | Runs in modern browsers; no C compiler needed |

## Architecture Overview

Fyne separates the application model from the rendering back-end through a `fyne.Driver` interface. When you call `app.New()`, the framework selects the appropriate driver at compile time:

- **Desktop (Windows / macOS / Linux)** — rendered with OpenGL (via GLFW) or Metal on Apple Silicon.
- **Mobile (Android / iOS)** — rendered with OpenGL ES through the platform's native window system.
- **WebAssembly** — rendered with WebGL inside a `<canvas>` element in the browser.

All canvas objects — shapes, images, text, and widgets — are represented as Go structs. Fyne walks the object tree on each frame and issues draw calls through the active driver. This design means you can unit-test your entire UI without a display, using the `test` package or the `-tags ci` build flag.

The `fyneApp` struct (in `fyne.io/fyne/v2/app`) owns the `Driver`, `Settings`, `Preferences`, `Storage`, and lifecycle hooks for your application. Each `fyne.Window` is created through the driver via `app.NewWindow()` and holds an independent canvas.
